## 内容量（2026-11-17最新反馈）

读者认可现阶段方向，但明确表示内容太少。各刊以8–12个可独立阅读的实质条目为常规策展目标，通常为1–2篇展开内容、4–6条项目/工具发现、2–3则知识或制作经验和一个文化小栏；按分刊职责及材料质量调整，不为达数虚构或拆碎同一选题。目录、来源、下载入口、同一实验按钮不计独立条目。信息流应同时有可扫读的短条和能展开的内容，不拉长导语、不重复流程说明、不用唱片扩篇。实验室以展开的真实项目或实验经验分享为中心，配源码/制作说明、工具发现、知识与文化短栏；不以自制小程序、控件或计算器填充内容量。

## 定位、读者与编辑判断

- 中文、移动端优先的独立技术知识文化杂志；用户和朋友每天阅读。硬件、源码、芯片逆向、开源制作、电子音乐及数字文化是范围，不是必须强行串成统一主题。
- 技术内容居主位。先展示技术简报、源码/原理图/测量与制作，再放唱片；音乐原则上不超过正文约15–20%。不是每日专辑网站或评分仪表盘。
- 每条说明“是什么、为什么值得关注、关键细节、读者能继续做什么”，有编辑判断而不只是链接堆砌或摘要改写。深读以实际代码、原理、测量、论文或制作记录为依据。
- 原文、项目源码、作者博客、厂牌和发行页优先；核实作者、日期、项目版本、URL和图片对象。Ken Shirriff、mitxela、cnlohr、Hackaday等是已使用的来源方向，不是必须每天复用的内容。
- 真实新闻与历史项目/经典回看分清，旧作不能写成今日新发现的发行新闻；不改日期假装新刊，不重复同日已收录内容，也检查近期期刊避免机械重复。
- 不编造试听体验、实验结果、性能、评分、排名、发行信息和已完成的核查。来源不足时缩减无依据论断或报告卡点，不靠虚构补齐。

## 音乐采集与筛选

1. 运行 `python scripts/collect_music_sources.py` 刷新 `data/music-radar.json`，按 `data/music-sources.json` 查看公开RSS候选。RSS标题、日期、分类、链接仅是线索，不等于完整读过乐评或已完成推荐。
2. 来源包括 Pitchfork（电子/实验与Best New Music）、Fantano/The Needle Drop原始视频/文字、Igloo（IDM/Glitch/Braindance）、A Closer Listen（实验/环境/田野录音）、Headphone Commute（电声/制作人）、The Quietus（Hyperspecific、Rum Music、磁带及地下场景）、Inverted Audio（地下舞曲、独立厂牌）。RYM/Sonemic、AOTY作为可访问时的补充线索，不以流行度或高分排除地下独立作品。
3. 逐篇核实候选属于乐评、新闻、首播、发行报道还是访谈。采访/新闻可提供选题，但不冒称专辑乐评。电子方向兼顾IDM、Glitch、Ambient、电声及SOPHIE相关实验取向，不机械按总榜选择。
4. 公开能读的就收集，不绕过付费墙和访问限制，不镜像整篇文章。不靠无日期社交转述补造RYM实时评分。
5. 评分仅可作为内部策展证据，存在时记录来源URL、原始分制、用户或媒体类别、样本数和核查日期；没评分就不编数字。Pitchfork文本0.0可能是占位，要核对原页rating.score；Fantano保留原始10分制，不把AOTY百分制当本人原分；失败标记时间和状态，不冒充新采集。精选证据可存 `data/music-radar-curated.json`。
6. 页面恢复轻量Bandcamp推荐：所有唱片，包括大媒体发现，均找到对应Bandcamp专辑页。真实封面、原始试听，播放器按需展开；不能嵌入时保留发行页链接，不用假封面或错误专辑播放器顶替。不是只有Bandcamp最新榜单，也不公开评分面板、榜单、评级说明或独立乐评系统。
7. 每张约40–80字，紧凑封面卡片，简述发行页About、制作背景、声源、编排、曲目或格式。没有About不编造，必要时在条目交代；未实际听过不得伪装听感。发布日期按发行页，旧作明确为回听/旧发行。乐评原文是次级“发现来源”。
8. 音乐定额严格晨3、午3、晚1、实验室0；覆盖过去七张/十张/每刊2–3张等旧方案，同日各刊不重复选片。每期保存 `bandcamp-selection.json` 的albums数组，发布登记musicCount，符合 `data/editorial-policy.json`。资料不足时报告，不能为凑数伪造。

## 文案禁区与图文设计

- 严谨、有趣、具体；可以写有根据的观察，不写空泛宣传、强行比喻和营销催促。禁止“直接开听”“小众唱片”等自我标榜，以及“统一回到Bandcamp”“真实封面、原始试听”“旧作不冒充今日新闻”等制作流程式导语。音乐栏标题使用“唱片 / RECORDS”。核查信息放具体条目，避免整段免责声明压过内容。
- 正文纯白，黑字、荧光绿标签，保留像素/等宽字体、瑞士网格与构成主义的清晰层级。图文要丰富：真实硬件照片、显微图、原理图、波形、屏幕/代码与唱片封面对应内容，不能退回只有长文字与少量装饰图。
- 参考分工：黑白硬件大图配荧光绿用于刊封面；纯白大字号SIGNAL / NOISE与简洁导语用于开篇；黑底真实唱片/作品卡可用于特别内容，不是每日大幅唱片必备。音乐不能重新挤占技术内容。
- 刊封面应有刊名、日期、期号、栏目/导读的杂志层级，手机完整展示；采用HTML/CSS与原创SVG排版，非强制生成一张插画。不恢复米白纸纹或花哨AI芯片封面。概念图与实物照片严格区分，来源显微图不能冒认成项目开发板。
- 每图有alt、对应来源URL、作者/版权归属，必要时同目录assets及credits.json留档；可用原文直达链接保留。图像失败保留说明和来源，不能悄悄换成不对应图片。
- 保留密集而可读的信息流、桌面侧边目录、手机目录与键盘操作，技术内容优先，图片尺寸适配，不横向溢出。继承当前 `static/morning/001/` 的实际图文组件，不重置整个视觉系统。
